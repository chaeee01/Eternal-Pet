# 01. 게임 개요

> 상태: 기획·설계 단계 (프로토타입 구현 전)
> 표기 규칙은 [README](../README.md#표기-규칙)를 따릅니다.

## 1. 한 문장 정의

반려동물의 사진과 추억으로 나만의 3D 펫을 만들고, 별의 세계에서 다시 만나 교감하며 모험하는 AI 기반 모바일 게임입니다.

## 2. 기획 배경

반려동물 사진은 수백, 수천 장씩 쌓이지만 특별한 날과 그날의 이야기를 다시 찾기는 번거롭습니다. 일반 펫 게임의 캐릭터는 귀엽지만 "내 반려동물"이라는 느낌은 약합니다.

Eternal Pet은 플레이어가 기억하는 반려동물의 생김새와 성격, 함께한 추억을 게임 안의 캐릭터와 이야기로 옮기는 것을 목표로 합니다.

## 3. 게임의 목표

| 구분 | 내용 | 표기 |
|---|---|---|
| 플레이어의 목표 | 내 반려동물을 닮은 펫과 교감하며 추억을 다시 경험한다 | 기획 |
| 플레이어의 행동 | 기억 등록 · 외형 꾸미기 · 대화 · 미션 | 기획 |
| 게임의 피드백 | 기억을 담은 대사 · 반응 · 추억 장면 | 기획 |

## 4. 타깃 플레이어

이전 제품기획서(2026-11-07)와 게임 기획 덱(2026-11-19)에서는 두 사용자군을 나눠 검증하기로 했습니다. 현재 기획에서도 이 구분을 유지합니다.

| 사용자군 | 주요 동기 | 설계 시 주의 |
|---|---|---|
| 현재 반려동물과 함께 사는 사람 | 산책, 첫 만남, 생일처럼 늘어나는 사진을 추억 단위로 남기고, 닮은 펫과 짧게 교감 | 별의 세계를 이별 이후의 공간으로 강요하지 않음 |
| 반려동물을 떠나보낸 사람 | 추억을 보존하고 원할 때 다시 들러 회상 | 이별 재현이나 엔딩을 강요하지 않음. AI 대화는 실제 반려동물이 아닌 가상 표현임을 분명히 함 |

어느 사용자군을 먼저 공략할지는 정하지 않았습니다 (**검증 예정**).

## 5. 핵심 가치와 차별점

| 핵심 가치 | 설명 |
|---|---|
| 내 반려동물을 닮은 캐릭터 | 대표 사진에서 뽑은 특징으로 3D 펫의 외형을 개인화하고, 플레이어가 직접 고친다 |
| 나만의 추억이 콘텐츠가 됨 | 플레이어가 등록한 기억이 대사, 미션, 스토리의 재료가 된다 |
| 근거 있는 대화 | 펫은 저장된 성격과 추억만을 근거로 말하고, 기억에 없는 사실은 지어내지 않는다 |
| 언제든 돌아올 수 있는 공간 | 미접속 불이익과 돌봄 실패 상태를 두지 않는다 |

### 기존 게임·서비스와의 차이 (가설)

| 비교 대상 | 일반적인 방식 | Eternal Pet의 방향 |
|---|---|---|
| 반려동물 소재 스토리 게임 | 정해진 캐릭터와 모든 플레이어에게 같은 서사 | 플레이어의 실제 반려동물을 닮은 펫, 개인의 추억 기반 미션 |
| 펫 육성·교감 게임 | 미리 만든 캐릭터를 고르고 돌봄 수치를 관리 | 사진 기반 개인화, 돌봄 실패 없음 |
| 사진 앱의 추억 기능 | 사진을 자동으로 모아 보여줌 | 기억을 플레이 가능한 장면과 대화로 연결 |

이 차별점은 아직 사용자에게 확인하지 않았습니다 (**검증 예정**). 구체적인 레퍼런스는 [07_REFERENCES.md](07_REFERENCES.md)에 정리했습니다.

## 6. 현실 세계와 별의 세계

| | 현실 세계 | 별의 세계 |
|---|---|---|
| 역할 | 기록하고 준비하는 공간 | 실제로 플레이하는 공간 (게임플레이의 중심) |
| 주요 기능 | 사진·일기·성격·기억 등록, 펫 개인화 정보 관리, 추억 타임라인 열람 | 3D 펫과 만남, 대화·교감·꾸미기, 추억 기반 미션과 스토리 |
| 데이터 | 기억과 외형 데이터를 만들고 수정·삭제 | 같은 데이터를 읽어 표시하고, 퀘스트 진행만 기록 |
| 구현 위치 (설계안) | 앱 화면 | Unity 씬 |

두 세계는 같은 저장 데이터를 봅니다. 자세한 구조는 [05_SYSTEM_ARCHITECTURE.md](05_SYSTEM_ARCHITECTURE.md)에 있습니다.

## 7. 사진·일기 서비스 기획에서 게임 중심 기획으로 확장한 이유

Eternal Pet은 처음부터 게임으로 기획한 것이 아닙니다. 기획은 다음 순서로 바뀌었습니다.

| 시점 (근거 문서) | 중심 경험 | 별의 세계의 역할 | AI의 역할 |
|---|---|---|---|
| 제품기획서 v0.1 (2026-11-07) | 사진 선택 → 날짜·장소별 추억 묶기 → AI 일기 초안 → 사용자 수정 | 추억을 감상하는 3D 공간 (P0에서는 독립 기술 데모) | 사실 중심 일기 초안. RAG 대화는 P2 이후 |
| 게임 기획·설계 덱 18장 (2026-11-19) | 추억 기록 + 3D "별의 정원" 꾸미기·교감 | 기억 1개 = 추억별 1개를 모으는 정원 | AI 일기 초안. AI 대화는 후속 후보 |
| 통합 포트폴리오 18~24쪽 (2026-11-20, 현재) | 3D 펫 개인화 + 별의 세계 대화·미션·스토리 | 게임플레이의 중심 | 기억 기반 대화가 핵심 콘셉트 ② |

확장한 이유는 다음과 같습니다.

1. **사진 정리만으로는 차별점이 약합니다.** 제품기획서에서 이미 iPhone 사진 앱이 반려동물 사진을 모아 보여주고 있어 단순한 분류는 독립적인 차별점이 되기 어렵다고 판단했습니다.
2. **"다시 열 이유"가 필요했습니다.** 제품기획서의 열린 질문 중 하나가 "별의 세계는 실시간 게임인가, 다이어리를 감상하는 3D 정원인가?"였습니다. 현재 기획은 별의 세계를 플레이 공간으로 정하고, 기억을 대화와 미션의 재료로 쓰는 쪽을 선택했습니다.
3. **기록은 남기되 위치를 바꿨습니다.** 사진·일기·기억 등록은 현실 세계의 기능으로 남겨 게임 콘텐츠의 입력이 되도록 했습니다.

각 결정의 대안과 남은 검증 항목은 [08_DECISIONS.md](08_DECISIONS.md)에 있습니다.

## 8. 아직 정하지 않은 것

- 먼저 공략할 사용자군 (현재 양육자 / 떠나보낸 사람)
- 이전 기획의 AI 일기 초안 기능을 현재 게임에 남길지 여부
- 플랫폼 확정 (이전 기획서는 iOS 우선, Android는 이후 검토)
- 엔딩이 있는 스토리와 엔딩 없는 상설 공간 중 무엇을 제공할지 (이전 기획서는 사용자 선택으로 분리하는 안을 제시)
